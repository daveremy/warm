# Further passages

Reducing the need for people's decisions as a goal:

- "A person cannot approve every call in a long run, so the server checks each one instead." [secure-deployment §Approve risky actions](https://platform.claude.com/docs/en/managed-agents/secure-deployment). The page recommends `auto` on `bash`, `write`, `edit`, `web_fetch` and read-only MCP tools.
- "Long sessions have too many events for a person to read, so the job has Claude read them." [secure-deployment-monitoring §Optionally have an offline reviewer read every transcript](https://platform.claude.com/docs/en/managed-agents/secure-deployment-monitoring). This reduces people's review of transcripts, not approvals.
- Release note: "Claude Managed Agents permission policies now include auto: the server evaluates each agent or MCP tool call and runs it, denies it, or pauses for your approval." [release notes](https://platform.claude.com/docs/en/release-notes/overview).

People's decisions should not be reduced:

- "auto is not a human checkpoint, so if a person must review a tool’s calls before they run, configure always_ask on that tool." [secure-deployment §Approve risky actions](https://platform.claude.com/docs/en/managed-agents/secure-deployment).
- "Have a person approve each call to a tool that can move money" (same section).
- "A client that allows every call without showing it to a person is the same as always_allow." (same section).

Other passages that bear on the ratings:

- Self-hosted console: "If a tool call waits for you, its card shows Approve and Deny." [self-hosted/console §Run an agent from the console](https://platform.claude.com/docs/en/managed-agents/self-hosted/console).
- Agent identity with single sign-on: "actor_sub doesn’t mean that the caller approved the call." [self-hosted/agent-identity](https://platform.claude.com/docs/en/managed-agents/self-hosted/agent-identity). The token names who created the session, not who approved a call.
- `reason_code` "is a value for your client to branch on and keep in audit records" [permission-policies](https://platform.claude.com/docs/en/managed-agents/permission-policies). The server stores the event; an audit record beyond the session history is the customer's to build.
- Self-hosted differences that affect monitoring: "The server sends no webhooks, so a worker that starts on a webhook never starts" [self-hosted/differences](https://platform.claude.com/docs/en/managed-agents/self-hosted/differences). The hosted `session.status_idled` webhook, which the monitoring page recommends for sessions waiting for approval, is not available; the differences page says to follow the event stream instead.
- Outcomes and graders: the grader is a model, not a person ("the harness automatically provisions a grader to evaluate the artifact against a rubric", [define-outcomes](https://platform.claude.com/docs/en/managed-agents/define-outcomes)). Not counted for any question.

Where self-hosted differs from hosted, for these ratings: session history is stored in the customer's database (in memory by default, lost on restart); no webhooks; no dreams; the console is on the customer's server. The ratings would be the same for the hosted service on H1 to H5, except that H3's note about dreams applies only to the hosted service (and dreams curate memory, not policies, so would not raise H3 there either).
